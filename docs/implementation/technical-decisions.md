# NC-PoRe Technical Decisions

## Deutsch ([English version below](#english-version))

Dieses Dokument war ursprünglich als Übersicht offener technischer Entscheidungen gedacht.

Die darin aufgeführten Grundsatzentscheidungen sind inzwischen über Architecture Decision Records (ADRs) dokumentiert. Das Dokument wird deshalb nicht länger als offene Entscheidungslandkarte gepflegt.

### Verbindliche Quelle

Für getroffene Architekturentscheidungen ist ausschließlich der jeweilige ADR maßgeblich.

Offene technische Fragen werden nicht vorab in einer separaten öffentlichen Liste festgeschrieben. Sie werden bei Bedarf als konkrete technische Fragestellung bearbeitet und, sobald daraus eine relevante Architekturentscheidung entsteht, durch einen ADR dokumentiert.

### Entscheidungsprinzipien

Technische Entscheidungen sollen:

- die fachlichen Anforderungen berücksichtigen
- nachvollziehbar begründet sein
- unnötige Komplexität vermeiden
- offene Standards und Interoperabilität bevorzugen, soweit sinnvoll
- langfristige Wartbarkeit und Sicherheit berücksichtigen

Die praktische Entwicklung und der aktuelle V1-Arbeitsstand sind in der Implementierungsdokumentation beschrieben.

# English Version

This document was originally intended as an overview of open technical decisions.

The architectural decisions listed there are now documented through Architecture Decision Records (ADRs). This document is therefore no longer maintained as an open decision map.

### Authoritative Source

For decisions that have been made, the respective ADR is authoritative.

Open technical questions are not maintained in advance as a public list. They are addressed when needed as concrete technical questions and documented through an ADR when they result in a relevant architectural decision.

### Decision Principles

Technical decisions should:

- consider functional requirements
- be traceable and justified
- avoid unnecessary complexity
- prefer open standards and interoperability where appropriate
- consider long-term maintainability and security

Practical development and the current V1 work state are described in the implementation documentation.
